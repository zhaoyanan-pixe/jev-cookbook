# 03 · 判定点清单：值得接的、别接的

> 一个多月下来，我们把"哪些地方接了划算"做成了一张清单。按收益从高到低排。

## 值得接的（按收益排序）

### 1. 搜索结果预排（rerank）★推荐第一个做
- **问什么**：一堆候选（搜索的十几二十条结果、召回的若干条资料）里，各自与目标的相关度？
- **怎么接**：在"拿到候选列表"之后、"送进阅读/上下文"之前。
- **观察效果**：单次搜索的阅读量明显下降；没发现漏掉关键结果的情况。
- **注意**：问题里要带**当前目标**（"关于 XX 的哪些结果先看"），不然它只能按泛泛的相关性排。

### 2. 工具/命令入场检查（影子起步）
- **问什么**：这个操作有没有破坏性/不可逆？该不该先停下来问人？
- **怎么接**：工具执行前的钩子；**第一周只记录不拦截**（影子模式）。
- **观察效果**：影子期抓到过若干"肉眼看不出"的可疑操作；误报率可接受。
- **注意**：**红线操作不进这套流程**——"花钱/发布/删除"永远走人工确认，不交给模型酌情。

### 3. 记忆与检索筛选
- **问什么**：召回的这一批资料，哪几条真的值得进上下文？
- **怎么接**：检索之后、拼上下文之前。
- **观察效果**：上下文占用明显下降；相关条目不丢（用账本核对的）。

### 4. 批量小判断（一次请求判一批）
- **问什么**：把"几十条小决定"打包成一次请求（每条一个小问题，或同一条多维打分）。
- **观察效果**：这是最省的一类——一次请求的成本摊薄到几十个决定上；且数条问题并行评估，几乎不增加耗时。

### 5. 上下文压缩选择
- **问什么**：压缩对话/文档时，哪些片段必须原样保留（关键约束、用户明确偏好、未完成事项）？
- **怎么接**：压缩前筛选；把"必须保留"的清单交给压缩器。

### 6. 路由/选择类（谨慎放权）
- **问什么**：多个工具/技能/处理路径都沾边时，走哪条？
- **注意**：这类我们实测**不齐**——同一"大问题"下，有的任务族可靠度 90%+，有的只有 15%（见 04 的族级评测）。**必须先分族评测，再按族放权**，别一把梭。

## 不适合接的

- **需要长链推理的**（数学推导、写代码、写文章、多步分析）——判定器是"秒级直觉"，不是"深度思考"；这类交给大模型。
- **决定性大事**（发布、付款、删数据、对外发送）——**红线永远走人工关口**。
- **你自己都说不清标准的问题**——先把"判定标准"写成人话，再交给它；写不出来的问题，它只会含糊。
- **要求 100% 正确的地方**——任何概率模型都不是证明器；重要的判定要有"兜底路径"。

## 新增判定点的记录模板（建议照抄）

```markdown
### N. 判定点名称
- 问什么（一句话）：
- 接在哪（时机/钩子）：
- 影子期结论（时间范围、样本量、命中率）：
- 什么情况下不要用：
- 失败时的兜底动作：
```

**给每个判定点配套"兜底动作"**——判定器说"拿不准"或"调用失败"时，回退到哪条老路？这张纸写完，才允许上线。
