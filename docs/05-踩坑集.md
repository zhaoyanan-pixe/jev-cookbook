# 05 · 踩坑集（含翻车实录）

> 以下每一条都是我们真实踩过的。按"疼的程度"排。

## 1. 钥匙与连通（最高频）

**症状 → 病因对照表**：

| 现象 | 大概率原因 | 怎么办 |
|---|---|---|
| `401 Unauthorized` | key 没设、设错变量名、或过期 | 确认环境变量名（`TYPESAFE_API_KEY` / `OPENROUTER_API_KEY`）、重新签发 |
| `403 Forbidden` | key 无权限 / 网关拒绝 | 检查平台面板里 key 的权限范围 |
| `429 Too Many Requests` | 触发限流 | 退避重试（别死循环）+ 熔断一段时间 |
| `422 Unprocessable Entity` | **请求格式不对**（最常见！） | 看下面的"格式坑" |

**格式坑（真实踩过，报错信息会精确告诉你缺什么）**：

- `choice` 的 **`criteria` 是字典**：`{"选项名": "该选项的说明或 null", ...}`——选项名就是字典的键；
- `score` 的 **`criteria` 是有序数组**：`["最差", "中等", "最好"]`（2–10 档）；
- `noul` 只需要 `instructions`（一个是否问题）；
- 所有题型共用一个请求：`{"state": ..., "questions": {"你的问题id": {...}}}`；
- **技巧**：422 的响应体里 `loc` 字段会精确指出"哪个问题的哪个字段"缺了/类型错了——**照它改就行**。

## 2. 别让它"假装很懂"

- 问题含糊 → 它会给出**接近 0 的置信度**（这是好事，等于喊"我拿不准"）；
- 但如果你**只看答案不看置信度**，就会把"瞎猜"当"判定"用；
- **做法**：代码里把 低置信度 → 人工/老路径。

## 3. 超时与熔断（我们用的参数，供参考）

- 单次调用超时预算：**~3 秒**（别让判定器拖慢主流程）；
- 连续失败 **3 次** → 熔断 **~2 分钟**（静默跳过）；
- 限流的 `Retry-After` 只等**很短**（比如 ≤2 秒），等不起就直接放弃这次判定；
- **铁律**：判定器不在线时，一切照旧（fail-open）。

## 4. Payload 的"安全上限"

被评估的 state 太长时（大量候选文本），**必须在代码里截断**——而且：

> **被截断的输入，绝不能产生"有利判定"。**

例：如果因为截断导致"危险命令的后半段没看到"，判定器说"安全"——**这是灾难**。做法：一旦发生截断，强制走"人工复核/老逻辑"，不采信任何自动判定。

## 5. 密钥卫生（最惊险的一次）

- 铁律：**不打印、不落盘、不进日志**。出问题时的排查信息里，永远只写「有无 / 长度 / 指纹前 8 位」，不写值；
- 我们真实见过"差点把 key 写进日志文件"的场面——现在的做法：
  - key 只在环境变量里；
  - 日志函数对疑似密钥的长字符串做**掩码**；
  - 定期跑一遍**密钥泄漏面扫描**（本仓库附了 `scripts/jev_key_sweep.py`）。

## 6. 红线不进判定流

- "花钱、发布、删除、对外发送"——**不进任何自动判定**，永远停在人工确认；
- 这不是"模型准不准"的问题，是**责任边界**问题：判定器再准，也不该替人做这类决定；
- 写法上：红线检查用**确定性代码**（清单匹配），不经过模型。

## 7. 隐私：state 里放什么，要想清楚

- 判定器是**外部服务**：你放进 state 的内容会离开你的机器；
- 做法：**只放判定所需的最小信息**；能脱敏就先脱敏（人名/账号/路径用占位符）；
- 内部机密、个人隐私、客户数据——**不进 state**。

## 8. 多问几件事 ≠ 更慢

- 同一请求里加问题（几十个）**几乎不增加耗时**（并行评估）——这是最容易被忽略的红利；
- 但**别把一整个复杂判断塞进一个难题**——拆成多个小问题，在代码里加权合并（"复合评分"）。

## 9. 账本要"常开"

- 不记账 = 没有放权依据；
- 记账但不回填"实际结果" = 白记（命中率无从算起）；
- 我们的做法：每条记录**当天留"待核对"**，一周内回填，族级统计自动出。
