# Jev Cookbook · 给 AI 助手装一个"小脑"

把 **Jev**（一个小而快的"判定器"）接进你自己的 AI 助手：哪些决定该交给它、怎么接、怎么验证、哪里会翻车。

> 一个多月的真实使用实战手册（2026-09 起）。不是概念介绍，也不是广告——你跟着读完，能自己跑通第一个判定点。

---

## 30 秒看懂

**Jev 是什么**——一个"只回答小问题"的判定器。你问它一个问题，它给出答案 + 一个概率：

- **是 / 否**——"这条命令危险吗？"
- **选一个**——"这几条搜索结果，哪条最相关？"
- **打个分**——"这段信息对当前任务有多重要？"

它不聊天、不写文章、不编故事——**只做判断**。每个答案都进账本：可追溯、可复盘、可翻案。

**为什么要它**——AI 助手每干一轮活，背后有几十个"碎决定"：

> 这条命令要不要先拦一下？搜到 20 条结果，先看哪条？刚才那段对话该留在上下文里吗？这个活到底干完了没有？

让大模型来做：又贵、又慢、还分心。写死规则：太笨，经常判错。
交给 Jev：**又小又快、一次只判一件事**，大模型把注意力留给真正的工作。

**这个仓库是什么**——我们把 Jev 接进自己的 AI 助手，用了一个多月，把全部经验放在这里：

- 接入指南（可直接抄）
- 值得接的判定点清单（含"别接"的清单）
- 影子期与评测方法（先确认它靠谱，再逐步放权）
- 踩坑集（含翻车实录）
- 可直接跑的小脚本

## 快速开始（3 步）

1. **弄一个 Jev 的入口**——TypeSafe 或 OpenRouter，任选（详见 `docs/02`）。没有 key 也能先跑通流程：部分平台提供免费入口，先用起来。
2. **验通**——把 key 放进环境变量（不要写进代码），跑：

   ```bash
   export TYPESAFE_API_KEY=...        # 或者 OPENROUTER_API_KEY
   python scripts/jev_smoke.py        # 看它返回一个带概率的答案
   ```

3. **接第一个判定点**——照 `docs/02` 挂上"搜索结果预排"或"命令入场检查"，跑影子模式（只记录、不拦截），观察一周。

## 我们跑过的判定点（概览）

> 详表与效果数据见 `docs/03`。以下是诚实摘要——**效果依场景而定，请以你自己的影子期数据为准**。

| 判定点 | 它在干什么 | 我们观察到的效果 |
|---|---|---|
| 搜索结果预排 | 一次搜索返回十几二十条，先让 Jev 排出"最值得先读" | 单次搜索的阅读量明显下降；漏掉关键结果的情况未发现 |
| 命令/工具入场检查（影子） | 危险、外发散、破坏性的操作先判一次 | 影子期抓到过若干"肉眼看不出"的可疑操作；误报可接受 |
| 记忆/检索筛选 | 一次召回多条资料，选出真正相关的 | 上下文占用下降；相关条目不丢 |
| 上下文压缩选择 | 压缩对话时，哪些片段必须保留 | 关键约束不丢 |
| 技能/路由选择 | 多个技能都沾边时选一个 | 选错率低于随机，但**不适合全自动放权**（见 docs/04） |

## 我们踩出来的 6 条原则

1. **失败必须安全（fail-open）**——Jev 挂了、超时了，就当"没有它"，绝不卡住主流程。
2. **先影子，后放权**——先在旁边记录它"会怎么判"，跟你的实际做法对照，再逐步采信。
3. **一类一类放**——按"任务族"分别达标再放。我们实测：有的族可靠度 90%+，有的只有 15%——**别一把梭**。
4. **便宜的问题才找它**——"要不要拦"、"先看哪个"这类小问；**定方向、拿主意的大事，别交给小判定器**。
5. **每条判断留痕**——输入、答案、概率都记下来。能复盘，才敢放权。
6. **红线不受弹性解释**——"花钱、发布、删除"这类硬红线**不进判定流程**，永远走人工关口；不把"该硬拦的"降级成"交给模型酌情"。
